# 全局离线模式 —— 本地化开关 实施方案

> 状态：待实施
> 目标项目：OpenBidKit_Yibiao（Electron 桌面端）
> 关联需求：用户希望软件完全本地化，开启后不发起任何外网请求、不泄露数据

---

## 1. 背景与问题

当前客户端启动和运行期间会主动发起多类外网请求（远程公告、升级检查、启动广告、埋点统计、模型信息、许可证激活、IP 封禁检查、资源/插件市场等，详见 §3 锚点清单）。虽然经代码审计，公告/升级/广告类请求均为纯拉取、埋点不含 API Key/提示词/正文/文件名（仓库硬性约定），但用户明确希望有一个"完全本地化"的开关，一键关闭除用户自己配置的服务之外的所有出网行为。

## 2. 目标与非目标

### 目标

- 配置新增 `offline_mode` 布尔开关（默认关闭，即现状行为不变）。
- 开启后，客户端不发起任何 `analytics.agnet.top`、GitHub、`oss.agnet.top`、`wiki.agnet.top` 等运营类外网请求。
- 受影响页面给出离线占位提示，不报错、不空转。
- 开关即时生效（无需重启），关闭后行为完全恢复。

### 非目标（本期不做）

- 不拦截用户自己配置的 AI 模型请求（OpenAI 兼容 API / Ollama / LM Studio 等），那是用户自己的服务。
- 不拦截 MinerU 在线解析（用户配置项）。
- 不拦截用户主动点击的外部链接（`openExternal`）。
- 不删除、不弱化任何埋点/统计代码——只增加用户显式选择的开关，默认行为不变（统计能力等价保留，开关关闭时上报照常）。

## 4. 总体设计

### 4.1 配置字段

- 在 `user_config.json` 增加顶层字段 `offline_mode: boolean`，默认 `false`。
- 权威实现：`client/electron/services/configStore.cjs` 的 `normalizeConfig`（L685，配置归一化唯一入口）增加默认值与布尔归一化（参考 `developer_mode` 写法）。
- 类型同步：`client/src/shared/types/config.ts` 的 `ClientConfig` 增加 `offline_mode?: boolean`。
- 不新增 IPC 通道：复用现有 `window.yibiao.config.load()` / `save()`。
- configStore 导出纯函数 `isOfflineModeEnabled(config)`，Main 侧各服务统一用它判断；`main.cjs` 启动期直接读 `readStartupConfigFile()` 的原始 JSON 判断（该阶段尚无完整 configStore 装配）。

### 4.2 抑制策略（分层）

**Main 侧（每次调用时读配置判断，即时生效）：**

1. `main.cjs`：offline 时跳过 `checkBlockedIpAfterStartup`。
2. `updateService.cjs`：checkUpdate 在 offline 时直接返回 `{ enabled: false }` 形态的结果，不发任何请求；下载更新入口同样前置拦截。
3. `aiService.cjs`：`/track` 与 `/model-info` 两个网络出口在 offline 时静默跳过（本地 token 统计、队列、重试逻辑完全不变，仅不上报）。
4. `agentErrorReporter.cjs`：offline 时跳过上传（本地诊断文件保留）。
5. `licenseService.cjs`：offline 时跳过自动远程刷新，仅评估本地授权；用户手动激活仍走原路径（会失败，有既有错误提示）。

**Renderer 侧：**

6. `UpdateNotifier.tsx`：每次轮询检查配置，offline 时不调 `window.yibiao.checkUpdate()`、不调 `fetchRemoteNotice()`、不上报送达；轮询器保留（开关切回在线后即时恢复）。
7. `analytics.ts`：`sendAnalytics` 前置检查，offline 直接返回；本地 client id 迁移逻辑保留。
8. 资源页：offline 时不请求，显示"离线模式已开启，资源页不可用"占位。
9. 插件市场页：同上，不请求 `/plugins`。
10. 捐赠/致谢页：offline 时显示离线提示，不请求 wiki 接口。
11. `StartupAdvertisementDialog.tsx`：组件内加 offline 守卫（不加载图片、不弹窗），为将来挂载预留。

### 4.3 设置页 UI

- 设置页新增"网络"分区（或并入既有通用分区，实现时按现有页面结构决定），用 `AppSwitch` 呈现"离线模式"开关。
- 文案：开启后不发起任何运营类外网请求（公告、升级检查、埋点统计、广告、资源与插件市场）；AI 模型与文件解析服务为你自己配置的服务，不受影响。
- 保存沿用设置页现有 `window.yibiao.config.save` + `useToast` 模式，即时生效。

## 6. 测试与验收

- 配置底座：旧配置文件无 `offline_mode` 时归一化为 `false`；写入后 load 往返一致。
- 开启离线模式：应用重启后，公告不弹、不检查升级、不弹广告；日志/网络面板确认对 `analytics.agnet.top`、`api.github.com`、`oss.agnet.top`、`wiki.agnet.top`、`atomgit.com` 零请求。
- 资源页/插件页显示离线占位，无报错。
- 埋点：offline 时 `/track` 零请求（Renderer 与 Main 两侧）。
- 关闭开关：公告、升级、埋点全部恢复，行为与现状一致。
- 默认（未配置/关闭）：行为与改动前完全一致。
- 验证命令：`node --check` 各 `.cjs`、`npx tsc --noEmit`、`npm run build`、`npm run smoke:electron-native`。

## 7. 风险与边界

| 风险 | 应对 |
|---|---|
| 开关生效时机 | Main 服务每次调用读配置（无需重启）；Renderer 轮询周期内生效（UpdateNotifier 现有轮询即触发） |
| 埋点统计口径 | 离线模式是用户显式选择的产品功能，不删除统计代码、默认行为不变，符合"等价保留统计能力"要求 |
| 资源/插件页面数据缺失 | 页面给出明确离线占位，不展示过期缓存 |
| 启动期竞态 | main.cjs 的 IP 检查用原始配置文件判断，发生在配置装配前，无竞态 |
| 未来新增出网点漏拦 | 本方案输出"出网请求清单"，后续新增运营类请求时需同步检查 offline 守卫（列入开发说明） |
