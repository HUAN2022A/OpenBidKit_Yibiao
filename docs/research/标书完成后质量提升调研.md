# 标书完成后质量提升调研：方法地图与现有实现差距

> **日期**：2026-09-11
> **范围**：面向中国工程 / 货物 / 服务类招投标，聚焦「投标文件已经写完之后，如何把它改得更好、更可能中标」这一阶段的方法体系，以及易标客户端当前实现与差距。
> **方法**：15 个 agent 的并行调研工作流——7 路精读相关子系统代码、6 路调研行业方法与法规依据、1 路差距分析、1 路完整性批判；关键代码断言由主会话二次核实。
> **可复现脚本**：`.claude` 会话目录下的 `bid-quality-after-completion-wf_15b228f5-031.js`（工作流脚本）。

---

## 0. 摘要与结论

**「标书完成后提质」在实务中是一套成熟的方法体系，不是零散技巧。** 它可以归成六族（A 符合性审查 / B 评分点对表 / C 技术方案二次提升 / D 查重与雷同 / E 商务标报价 / F 模拟评标与复盘）。

**现状判断：应用已覆盖其中「检查」的一半，但缺掉两条腿——**

1. **诊断 → 修复的链条断了。** 废标项检查、AI 评标、查重、一致性审计全部「只报告不改写」：finding 不落到可修改的正文节点，没有带整改要求的一键重写；且投标文件不能从技术方案正文回读。检出率无法转化为提分。
2. **纯规则类检查整块空白。** 报价算术/大小写/三表一致/限价、工程量清单 diff、暗标去名与格式核对、投标有效期与保证金要素核对——全仓零实现，而这恰是「零漏项、100% 可自动化、高频致命废标点」的部分。

**最高杠杆的一步**：做「评分点覆盖度报告 + 评分点响应索引表」。所有其他诊断（打分、去 AI 味、改字）都建立在「知道哪条评分点没写到」之上；但**前提是先给导出补目录域/页码**，否则索引表落不了地。

**产品护栏（必须内建，不得反向）**：`原创性提升 = 内容变好且来源清白；规避查重 = 内容没变好、只想让机器看不出来`。改写类功能必须设置来源合规护栏与改写前后相似度回测，拒绝对他人标书做伪原创。

## 1. 行业方法地图

每条标注：**做法要点** / **依据** / **可自动化程度**（面向桌面 AI 工具）。

### 1.A 符合性 / 响应性审查——防废标（损失最大的一族）

这一族**不影响得分，只决定出不出局**，实务中优先级最高。行业数据显示废标率约两成，且多数废标条款与方案质量无关，纯粹是「有没有做到」。

- **否决投标条款逐条核对清单**（行业叫「废标条款对照表」）——做法：从「投标人须知前附表」「评标办法前附表」「否决投标/投标无效专章」「投标文件格式与附录」及澄清补遗中，全文检索「否决投标 / 投标无效 / 不予受理 / 无效响应 / 重大偏差 / 实质性偏离 / 视为放弃」等关键词，逐条摘录成表（序号｜条款原文｜章节页码｜分类｜可自检/需平台/需现场｜投标文件对应位置｜自查结论｜责任人｜整改状态），未响应项升级为整改项，定稿前清零。依据：《招标投标法实施条例》（国务院令 613 号，2019 修订）第五十一条七类否决情形、《招标投标法》第二十七条、七部委 12 号令《评标委员会和评标方法暂行规定》第二十三条。自动化：**高**（条款抽取 + 正文逐条核验 + 证据定位）；签章/密封/纸质正副本/现场递交只能列清单+提醒。
- **形式评审自查**——做法：投标函签字盖章与日期、法定代表人身份证明与授权委托书要素、招标文件要求的每个表格式样是否一份不少、正副本套数、装订密封与骑缝章、电子标专项（CA 证书有效性、电子签章覆盖面、能否正常打开、加解密与上传回执）。依据：《招标投标法》第二十七、二十八条；12 号令第二十五条把「未授权代表签字盖章」「未按要求提供投标担保」列为重大偏差。自动化：**低–中**（线下/平台动作无法代做，只能生成检查单与勾选记录）。
- **资格评审自查**——做法：建资格条件对照表（招标要求逐条 → 应提交材料 → 材料位置 → 有效期截止日 → 是否满足）；核营业执照经营范围覆盖、资质证书等级与许可范围且**有效期覆盖投标截止日/投标有效期**、关键人员证书注册单位为投标人且**社保连续 N 个月**、业绩的数量/类别/规模/**时间窗口**、财务报告年度与审计、信用与无违法记录声明。依据：条例第五十一条第（三）项、《招标投标法》第二十六条。自动化：**中**（清单与有效期/时间窗口可规则比对；证书与业绩真伪不可核验）。
- **响应性评审与偏离表核验**——做法：抽取实质性要求（工期、质量标准、投标有效期、质保期、付款方式、履约保证金、关键技术与性能参数、强制标准），逐条建「招标要求 → 投标应答 → 偏离结论（正/负/无）→ 说明 → 证据位置」表，重点查漏项与答非所问；商务条款检索「招标人不能接受的条件」；工期/质量/有效期做 ≥/≤ 规则比对。依据：《招标投标法》第二十七条、12 号令第二十五条、条例第五十一条第（六）项。自动化：**高**（偏离表结构化程度越高，自动核验越可靠）。
- **报价算术复核 + 大小写/单位/币种一致 + 限价比对**——做法：金额三处互核（投标函大写+小写、开标一览表、清单合计）；逐项核「单价×数量=合价」「分部汇总=总价」；单位币种统一；总价是否超最高投标限价/控制价；折扣必须落在开标一览表总价而非仅备注；按招标文件修正规则预演（大写优先于小写、单价优先于总价、中文优先）。依据：条例第五十一条第（五）项、12 号令第十九条修正规则、财政部 87 号令第五十九条。自动化：**高，最该优先自动化**（纯规则零漏项）。
- **投标保证金与投标有效期一致性核查**——做法：保证金金额（不超估算价 2%）、形式、是否从基本账户一次性转出、收款要素是否抄错、**是否在截止时间前到账**、保函受益人/项目/金额/有效期（≥投标有效期、一标段一保函）；投标函承诺有效期 ≥ 要求。依据：条例第二十六条、12 号令第二十五条第（一）项。自动化：**低–中**（到账属银行/平台事实，只能核对凭证要素 + 倒计时提醒）。
- **联合体合规核验**——共同投标协议必备且明确分工责任签章、各成员资格、同专业按较低资质定级、成员是否一标多投。依据：《招标投标法》第三十一条、条例第五十一条第（二）项、第三十七/三十八条。自动化：**中**。
- **分包合规核验**——招标文件是否允许分包及范围、是否载明拟分包内容、是否非主体非关键、分包人资格、是否承诺不再分包。依据：《招标投标法》第三十条、条例第五十九条。自动化：**中**。
- **暗标/匿名（盲评）合规检查**——做法：全文检索可识别信息（投标人全称简称、Logo、项目部名称、人员姓名、地址、电话传真邮箱网址、银行账号、页眉页脚、水印、印章、图签）；检查文档属性/元数据与图片属性；核对暗标格式要求（字体/字号/行距/页边距/页数/图表处理）。依据：多地暗标盲评规范性文件（内蒙古锡林郭勒盟、成都、通辽等）与招标文件「技术标出现投标人名称等信息的作否决投标处理」。自动化：**高**（纯文本匿名检查高度可自动化；图像内文字需 OCR）。
- **目录—正文—附件一致性交叉核对**——按招标文件「投标文件组成/格式」清单核目录项与正文章节一一对应、页码一致、附件存在且清晰完整、正文引用附件都能找到、正副本内容一致。自动化：**中**（缺章/缺附件可检；扫描件清晰度与页序错乱需人工）。
- **电子投标文件技术性自检**——平台指定工具生成、电子签章验签、加密—解密测试、文件大小与标段正确、上传回执、备份加密前源文件。自动化：**低**。
- **AI 辅助「项目专属核查清单生成 + 逐项核验」流水线**——本族的方法学总结：解析招标文件 → 抽取否决条款/实质性要求/资格条件并按形式/资格/响应性/报价分类 → 生成项目专属清单 → 对已完成标书逐条核验（能纯文本判断的给结论+证据定位，涉及签章/密封/纸质/现场/平台/银行事实的标注「不纳入电子文件检查」）→ 输出分级风险清单 + 整改建议 → 澄清补遗后重跑。自动化：**高**（文本类高自动化，事实类不可自动化）。
- **三级复核 / 背靠背盲审制度**——编制人自检打勾 → 未参与编制的复核人用同一清单独立复核 → 负责人终审（重点看高风险项与两人结论不一致项）→ 高风险项双人签字 → 定稿后静置再通读、有条件打印纸质通读。依据：企业内部质量控制惯例（经验之谈），与 ISO 质量管理一致。自动化：**低**（流程与人的管理，AI 只提供清单、不一致项汇总、提醒与留痕）。

### 1.B 评分点对表与覆盖度——提分核心

- **评标办法三段拆解**（技术分/商务分/价格分）——定位评标办法章节确认方法类型（综合评估法/综合评分法/经评审的最低投标价法）；拆三块权重并核对分值总和；单列价格分算法（基准价规则、K 值下浮、偏差扣分函数）；记录政策加成（中小企业价格扣除、监狱企业、联合体/分包加分）；判断技术标权重以决定投入优先级。依据：《招标投标法》第 40、41 条、《政府采购法实施条例》第 34 条、财政部 87 号令第 55 条（**货物项目价格分占比不得低于 30%、服务不得低于 10%**）。自动化：**高**。
- **评分点台账**——把评分表逐条抄成台账并编号（技-1、技-2、商-1、价-1），每条字段：序号 / 评分因素 / 分值 / 评分标准原文 / **数据来源（章节·条款·页码）** / 属性（客观 or 主观）/ 所需证明材料 / 是否「缺少相应内容即不得分」；明确切割三类内容（资格条件—合格性门槛、实质性响应要求、评分因素）；标出「硬缺项零容忍条款」（如「缺少相应内容的评审要点不得分，其他各项得分不应低于该要点满分的 70%」）与篇幅/形式扣分。依据：条例第 49 条「招标文件没有规定的评标标准和方法不得作为评标依据」、财政部 87 号令第 55 条（资格条件不得作为评审因素）。自动化：**高**。
- **评分索引表（应答索引表）**——四列（实务常做六列）映射：评分点编号与名称 / 对应投标文件章节与页码 / 响应内容摘要 / 得分证据及页码 / 自评；置于标书前部；每份证明材料前写明「本材料用于证明评分项 X（X 分）」；目录页码、索引表页码、正文实际页码三者一致（用自动目录避免手工错位）；定稿时以索引表为基准做反向抽查。依据：**真实招标文件常强制要求**——「评分标准中如要求提供证明材料的，需提供索引到投标文件对应页码的准确索引」（北京市政府采购、中央政府采购项目）。自动化：**高**（工具内章节天然可追溯，但需导出侧支持页码）。
- **评分点与目录结构对齐**——目录节点与评分项显式对应（节点名用评分项名，或标注对应编号）；顺序尽量跟随评分表顺序；三层固定节奏（评分点响应 → 针对性措施 → 保障/承诺）；章首放「本节响应评分项：X（X 分）」。依据：编标实务通行做法 + 招标文件格式规定（经验之谈）。自动化：**高**（目录权威在 `technical_plan_outline_nodes`）。
- **评分点覆盖度双向自检**——正向（评分点→正文）：每条确认有对应章节、有针对性措施而非通用描述、有支撑证据或承诺；反向（正文→评分点）：每个章节能挂到某个评分点上，挂不上的属跑题内容；关键词命中检查（把评分标准拆成量化指标逐条确认正文有对应表述）；三态标注（完全/部分/未响应）；红线校验（缺项零容忍项为「未响应」即不允许定稿）；跨章节事实一致性。依据：《招标投标法》第 40 条、条例第 49 条；缺项扣分规则见真实招标文件。自动化：**中高**（覆盖率统计、章节挂点、关键词命中可自动；「是否答到点子上」需人工确认）。
- **加分项最大化呈现**——建企业加分项台账（业绩、获奖、专利、软著、ISO 三体系、行业专项资质、信用评级），标注有效期与覆盖范围；逐条对照评分表的证明材料要求（形式/数量/时间窗口/金额门槛/同类界定）；**业绩三证齐全原则**（合同 + 中标通知书 + 验收/用户报告，缺一可能按无效业绩不计分）；认证有效性核验（有效期、认证范围是否覆盖采购标的）；显式关联评分项；佐证集中成卷并进入索引表。依据：财政部 87 号令第 55 条、《政府采购法》第 22 条（资格条件不得作为评审因素）。自动化：**部分**（要求抽取与企业台账比对可自动；证书扫描件内容核验需人工）。
- **面向评委阅标习惯的文档组织**——结论与响应前置、关键指标表格化；目录层级到三级且页码一致并配索引表；章节编号与页眉标注所属评分项；客观材料集中成卷配清单页；控制篇幅避免大段散文；按评标分工组织目录（方案类/措施类/团队类分组）；预留「评委快速核对区」（索引表 + 承诺一览表 + 参数偏离表）。依据：合肥市公共资源交易中心公开表述「综合评分法类似笔试，招标文件是试卷，投标文件是答卷，分数高低取决于答案与试卷答案的相符度」；评委时间有限、按表打勾为行业普遍经验。自动化：**中高**。
- **编标终检三查制度**（自检 / 互检 / 专检）——编制人对照台账逐行打勾；未参与该部分的同组人员「扮演评委」严格按评分表顺序找内容并打分；投标主管做红线校验；三签闭环留痕；任何修改后重跑覆盖度自检（修改可能破坏页码索引与一致性）；开标后回收实际得分反哺台账。自动化：**部分**。

### 1.C 技术方案正文完成之后的二次提升

**关键判定：哪些改字就能做，哪些必须回策划。** 判定准则——**若修改会改变「干什么、怎么干、投多少、花多少钱」任一项，即属方案实质变更，必须回策划阶段（并与商务标联动重新组价）**。

**二次审查/改字即可：**

- **项目信息「落地化」改写**——建「项目事实清单」（工程名称、地点、地形地貌、地层与地下水位、周边相邻建筑/道路/管线/居民区、面积/层数/结构形式、基坑深度、总工期、质量安全目标、危大工程）；全文检索泛称（本工程/该项目/建筑物）在其后补入具体参数；每章开头补「结合本项目 XX 现场条件」；排查「错配专业段」（无地下室却写降水、无桩基却写打桩、无幕墙却写幕墙工艺）。依据：《招标投标法》第二十七条、GB/T 50502-2009《建筑施工组织设计规范》；多地评标办法设「方案针对性/针对项目实际情况」独立评分项。自动化：**高**。
- **重难点分析 + 对策（四段式）**——从招标文件、地勘、图纸、答疑、踏勘纪要提取真实重难点（深基坑/高支模/大跨度/临地铁/管线改迁/雨季汛期/交叉作业/危大工程），每个按「难点描述 → 对本项目的具体影响 → 技术对策 → 资源与组织保障 → 责任人/时间节点」成文；对策必须落到工法、机械、材料、检测手段，不能只写管理口号；与施工方法、进度、资源配置三章互相呼应；确保危大工程全部在场并注明将编专项方案。依据：住建部令第 37 号第十条（危大工程须编专项方案）、《建设工程安全生产管理条例》国务院令第 393 号第二十六条。自动化：**中高**（候选生成可自动，可施工性须技术人员审定）。
- **招标文件「响应点」逐条回标**——抽出所有「应/必须/不得/★/▲/否决项」技术条款，逐条在正文定位，做「响应/部分响应/未响应」台账，未响应或含糊项补写明确响应句与证明材料，核对偏离表与正文一致。依据：《招标投标法》第二十七条、条例第五十一条第（六）项。自动化：**高**。
- **工期与进度计划自洽核验**——计划总天数 = 招标工期、开竣工日期与投标函/商务标一致；是否附横道图或双代号网络图并标注关键线路与总时差；用工程量 ÷ 日产能反算关键工序持续时间与班组人数、机械台班是否算得通；季节性与社会因素（雨季/汛期/冬期/节假日/中高考停工）是否预留；与劳动力/材料/机械投入曲线对应。依据：多地评标要点明文「采用网络图或横道图，关键线路清晰」；GB/T 50502-2009。自动化：**中**（工期数字一致性可自动；网络图绘制与关键路径计算需专业工具）。
- **资源配置一致性核验**——建资源台账（分工种劳动力、主要材料量、主要机械型号台数、试验检测设备、周转材料），与进度时间节点一一对应，与商务标措施费/机械费/人工费口径核对，按工程量反算数量合理性，全文同一资源数量必须一致。自动化：**高**（一致性比对）。
- **施工部署与总平面布置图逻辑自洽**——核对施工分区与流水段在部署文字、平面图、进度计划中一致；检查平面图要素（围墙大门、施工道路、加工区、堆场、临水临电、消防、办公生活区、塔吊/施工电梯覆盖范围）；是否分阶段绘制；塔吊选型附着与结构高度匹配。依据：GB/T 50502-2009。自动化：**中**（文字一致性可自动；图形判断低）。
- **质量/安全/文明/环保目标承诺一致性**——抽出投标函/商务标/合同条款中的承诺与技术标逐项比对；目标等级与措施匹配（争创鲁班奖须有创优策划、样板引路、实测实量制度）。自动化：**高**（承诺一致性比对）。
- **全文关键数据一致性自查**——列「关键事实台账」（项目名称、地点、工期、开竣工、质量目标、主要人员、主要设备、关键工程量），全文逐项比对同一事实的不同表述，重点核对表格/图题/图内数字与正文，交叉核对商务标与投标函。依据：多省电子投标文件雷同认定意见（甘肃甘发改法规〔2024〕843 号、贵州黔发改法规〔2024〕296 号）。自动化：**很高，本仓已有对应实现**。
- **图表化改造（图文并茂）**——按评分要点列应配图清单（施工总平面布置图分阶段、进度横道图/网络图、主要分项工艺流程图、项目组织机构图、质量/安全/环保保证体系框图、关键工法示意图、劳动力/资源投入曲线、监测点布置图）；每图配图号图题图例比例尺；图文数据一致；暗标项目图中不得出现企业名称标识人名。自动化：**部分**（流程图/体系框图/组织架构图可生成；总平面布置图、工艺示意图需专业绘图）。
- **去模板味改写**——识别高雷同段落（满是「认真贯彻/精心组织/确保万无一失」类空话、无本项目专有名词）；逐段替换为注入本项目专有名词、工程量、现场条件、企业既有做法的表述；删除与招标文件原话大段重复的文字。依据：多省雷同认定意见。自动化：**高**（但改写必须注入真实项目信息，否则即洗稿）。
- **去 AI 味改写**——标记 AI 高频套路（三段式排比、「不仅…而且…」「综上所述」、每段等长、抽象形容词、正确但无信息量的句子、破折号滥用）；改法：抽象形容词换成具体数字/型号/规范号；长排比拆成有主次的短句；补入只有干过该工程才知道的细节。依据：公开经验之谈（知乎讨论、开源中文 AI 写作痕迹清单），**无权威标准，可靠度 medium**。自动化：**高**。
- **暗标化/去名化与格式合规处理**——通读招标文件暗标章节；全文搜索企业名称/商标/人员真实姓名/可识别业绩；检查封面、页眉页脚、图签、水印、电子属性（作者/公司/创建者）是否清除；核对字体字号行距页边距页码位置装订。依据：多地暗标盲评规定。自动化：**高（文本检索 + 元数据清理）；格式合规需与实际排版核验**。
- **专业术语与规范名称/标准号准确性校核**——抽取全文标准号（GB/GB-T/JGJ/CJJ/JTG 等）、规范名称、工法名称、材料设备名称，逐条核对是否现行有效版本；统一术语口径。依据：GB/T 50502-2009；「术语错误招评委反感」为从业共识。自动化：**中**（现行性核验需联网或现行目录）。
- **篇幅与页面控制**——查明招标文件对总篇幅、各评分点篇幅、字数、是否允许附录的规定；统计当前页数/字数并按评分点权重分配；压缩低权重模板化内容；页数限制严时把可外置内容放入附录/图纸册（先确认是否允许）。依据：招标文件明文篇幅扣分实例（徐州项目「总篇幅不超过 65 页，每超过 1 页扣 0.1 分」；江苏「施工组织设计总篇幅一般不超过 80 页」）。自动化：**高（页数/字数统计与上限比对）；但需导出侧能统计页数**。
- **模拟评标/自评**——把技术标评分细则拆成台账，逐项对照正文自评或 AI 模拟评分，标注「缺项/薄弱/达标」；缺项优先补写，薄弱项加厚深化；复核「缺项零容忍」「不低于满分 70%」硬约束；迭代至无缺项。自动化：**很高，本仓已有 AI 评标**。

**必须回策划阶段：**

- 施工分区/流水段划分与施工顺序
- 塔吊等主要机械选型与布置
- 主要施工工艺与工法选择
- 进度网络计划的关键线路与工序搭接关系重排
- 真实资源投入（人数/设备）调整
- 新技术亮点选点与落地承诺
- **任何影响成本的方案变更（须与商务标重新组价联动）**

- **技术亮点/创新点注入**——对照评分细则看是否有「新技术应用/创新/绿色施工/信息化」加分点；结合本项目与企业能力选 2–4 个真能落地的亮点（BIM 深化设计与碰撞检查、装配式、铝模+爬架、智慧工地平台、绿色施工二星/三星、数字化质量追溯）；每个亮点写清「应用部位 + 技术路线 + 软件/设备 + 量化效益（工期/成本/质量）+ 责任团队」；与工期、成本、资源呼应；涉及成本增加或工艺变更的必须与商务标联动重新组价。依据：《绿色建筑评价标准》GB/T 50378-2019（2024 年版）加分项；多地评标要点含「工艺创新、装配式建筑等技术创新的应用实施措施」。自动化：**中**（选点与承诺需企业决策）。
- **货物/服务类技术参数点对点应答与售后服务方案深化**——建「招标技术参数 — 投标响应参数 — 偏离情况 — 证明材料」逐条对照表；正偏离说明价值，负偏离评估是否触发废标并给替代方案；服务类补实施方法论、项目管理机制、人员配置与资质、响应时效 SLA、质量保障与验收、知识转移与培训、应急预案。依据：财政部 87 号令；货物/服务类普遍设「技术响应/偏离表」评审。自动化：**高**（逐条参数对应与偏离统计）。
- **桌面 AI「评分点—正文覆盖度」自动检查的可行边界**（方法学结论）——可靠自动化：评分点抽取与结构化、章节定位、覆盖率统计与缺失/弱响应清单、结构与合规提示。需人工确认：「是否答到点子上」的语义判断、客观分事实核验（证书多存于图片/扫描件，文本解析可能丢失）。**不宜交给 AI**：直接给出「能得多少分/是否中标」的结论；对签字盖章密封纸质现场做自动判定。落地建议：以「覆盖度线索 + 证据定位 + 置信度标注」形式输出，明确声明 AI 不是评审结论。

### 1.D 查重与雷同（有法定红线，也有产品护栏）

- **「视为串通投标」法定六情形自查**——逐条核对：①不同投标人的投标文件由同一单位或个人编制；②委托同一单位或个人办理投标事宜；③载明的项目管理成员/联系人为同一人；④**投标文件异常一致或投标报价呈规律性差异**；⑤投标文件相互混装；⑥保证金从同一单位或个人账户转出。依据：《招标投标法实施条例》第四十条（政府采购对应财政部 87 号令第 37 条、《政府采购法实施条例》第 74 条）。命中任一条即应整改或放弃，不得赌概率。自动化：**部分**（全文相似度、报价数列规律检测、人员姓名实体交叉比对、元数据同源可自动；「是否委托同一人」「账户是否同一」需人工）。
- **电子投标文件雷同认定（机器码/IP/计价软件加密锁/制作标识码）**——不得与他人在同一场所、同一公网 IP 上传；不得用同一台电脑制作（评标系统采集网卡 MAC、CPU 序列号、硬盘序列号）；不得用同一把计价软件加密锁（广联达/品茗等锁号被读取）；「制作机器码/创建标识码/文件制作时间」不得异常一致；上传时间不得异常接近且 IP 相同。依据：甘肃甘发改法规〔2024〕843 号七种情形、贵州黔发改法规〔2024〕296 号。自动化：**工具无法读取平台侧机器码，只能做本机自查/模拟预警**（解析投标文件内嵌元数据判断是否可能与他人文件同源）。
- **文档属性与隐藏指纹自查**——文件属性（作者、最后修改人、公司、管理者、模板名）；Word 的 **RSID**（编辑会话指纹）；**OLE 复合文档流路径与大小指纹**；PDF 的 Producer/Creator、文档 ID、创建/修改/打印时间、权限位；嵌入图片的感知哈希与 EXIF；批注、修订痕迹、隐藏文字、自定义属性。交付前统一「另存为无历史的新文件」清理。依据：公开技术资料与专利（CN115249007A、CN117371422A）。自动化：**高度可自动化，是本类桌面工具最成熟的能力**。
- **技术标暗标评审下的统一格式合规编制**——技术标（暗标）与商务标（明标）分开制作；暗标不得出现投标人名称、徽标、人员姓名、单位简称；统一字体字号行距页边距；按当地要求决定是否可有目录/页眉页脚/页码；不得彩色文字、加粗倾斜、特殊边框、涂改、行间插字或删除痕迹。依据：通辽市《工程建设项目技术标暗标制评审办法》、成都市住建局「暗标盲评」规则。自动化：**中高**（格式体检可自动，「是否有别于他人的做法」需人工）。
- **投标人之间两两横向比对**——把自己与同为本次投标的其他主体（关联企业、挂靠人、合作方）一起两两比对；维度覆盖正文段落、表格、图片（OCR）、命名/节点、**语义（识别换词调序的改写抄袭）**；重点定位最长公共子串型连续雷同、关键技术与服务承诺段落、**连错别字都一致的片段**；对命中段落逐条溯源（引用招标文件/国标属正常，属别人原创须删改，属我方原创可反证）。依据：甘肃 843 号、贵州 296 号要求交易中心解密后向评标委员会提供雷同性提示。自动化：**高度可自动化，是本类桌面工具的核心场景**。
- **与自有历史标书库的纵向比对**——建企业标书库并归档；新标书定稿前比对历史项目名称、招标人名称、地名、工期、报价、人员名单、设备型号是否残留；关键技术参数/工艺/承诺是否已按本次招标逐项更新；可复用企业通用素材与项目专属内容分目录管理。依据：实务共识（复用旧模板本身不违法，风险藏在细节）；否决依据为「未实质性响应」。自动化：**高度可自动化，且适合本地私有库（可不出网）**。
- **查重软件的判定粒度与原理**——四个粒度：①**重合率**（预处理后按字符/句子/段落统计重复占比，常用余弦相似度、Jaccard）；②**雷同段落/最长公共子串**（连续多句逐字相同或高度相似，是法律「异常一致」的抓手）；③**文本指纹**（滑动窗口取 shingle，用 SimHash/MinHash 哈希成文档指纹，**换词、调语序、同义替换后指纹仍相似**）；④图片感知哈希 + 语义相似度 + 元数据/机器码（比文字更早暴露同源）。常见默认预警值：全文相似度超约 30%、核心段落超约 50%（红线以招标文件和平台规则为准）。依据：标事通《标书查重到底在查什么》、专利 CN117371422A / CN115249007A。自动化：**高度可自动化**。
- **相同错别字/相同笔误自查**——重点核查易被复制的区域（模板占位符未替换、单位名称/金额大小写、工期天数、技术参数笔误、表格公式错误、条目编号错乱、图片标题与正文不符）；与本次投标的其他主体文件交叉核对错漏是否相同：甘肃 843 号明确「两处以上错、漏内容一致」即视为雷同。自动化：**中**。
- **合规原创性提升（正道）**——①素材来源清白（自研/公开通用/已授权）；②对每个评分点用本项目专属信息填充（项目名称/地点/规模/地质水文/工期节点/业主特殊要求/周边环境/风险点）；③技术方案写「做法+措施+资源+验收标准」；④形成「评分点—响应段落—证据材料」对照表；⑤对从网络/同行/旧稿获取的段落只取其「知识」，用自己的语言结合本项目重写。自动化：**高度可自动化，是 AI 工具最有价值的方向**（定位为「辅助原创」而非「机器降重」）。
- **结构与表述改写（有前提）**——调整章节层级与叙述顺序、并列改表格/流程图/时间轴、合并同义段、补充企业独有工艺参数与案例数据、统一行业规范术语；**切忌只做同义词替换/语序颠倒的伪改写**（指纹与语义相似度仍会命中）。前提：素材来源必须清白，否则即变成违规洗稿。自动化：**高度可自动化，但必须设护栏**（改写前后指纹相似度回测 + 拒绝「对他人标书伪原创」）。
- **企业自有素材库的合法复用**——建自有知识库（公司简介、资质荣誉、组织架构、体系文件、通用工艺库、标准作业程序、自研图表模板）；**每一入库素材登记来源与权属**（自研/公开通用/授权采购），禁止把「从同行标书下载的段落」入库；图片建立自有版权台账。依据：海南自由贸易港知识产权法院判例——员工离职后用前雇主 PPT 模板，致两家公司在同一项目投标文件部分雷同被退标，法院认定涉案流程示意图为受著作权法保护的图形作品，判赔 20 万元。自动化：**高度可自动化**（素材库 + 权属标签 + 来源登记 + 残留检测 + 同源图片比对）。
- **自用历史标书模板复用的合法性与红线**——①同一投标人把过往标书当模板自我复用：通常允许，但必须按本次招标更新所有项目专属信息；②**红线一**：同一项目/标段中若两个及以上「不同投标人」（含同一控制人下的关联企业、夫妻/亲属控股企业、挂靠人、共用编制人员）的投标文件相互雷同，即触发第 40 条视为串通；③**红线二**：同一项目不同标段，若招标文件规定「同一投标人只能中一个标段/须分别独立编制」，或不同标段被不同投标人投（实为同一伙人操控），仍会被认定串通；④单位负责人为同一人或存在控股、管理关系的不同单位，不得参加同一标段投标或未划分标段的同一招标项目投标。依据：条例第三十四条第二款、第四十条；政府采购对应 87 号令第 37 条。
- **绝对不能做（三条）**——①**串通投标**（协商报价与方案、陪标围标、借资质）：中标无效、罚款、取消 1–3 年投标资格直至吊销营业执照、可追刑责（《招标投标法》第 32、53 条，条例第 39–41、67 条）；②**抄袭特定投标人方案**（著作权/商业秘密侵权）；③**伪造业绩/人员/财务等弄虚作假**（条例第 42、68 条，《招标投标法》第 33、54 条）。工具能做的是风险提示与自查清单，**绝不能提供任何协助串通的比对/规避功能，也不得提供伪造/拼接证明材料的能力**。
- **明确区分：合规的原创性提升 vs 违规的规避查重**（三问判定）——①**素材来源**：自研/公开通用/已授权，还是来自特定他人或网络未授权内容？②**内容实质**：改后是否注入本项目真实信息、比原方案更贴合评分点（真实提升），还是只做同义词替换、语序颠倒、机械扩写以降低重合率（伪降重）？③**行为目的**：是提升方案针对性与原创性，还是为了与其他投标人「错开」以掩盖同源？界线一句话：**原创性提升 = 内容变好且来源清白；规避查重 = 内容没变好、只想让机器看不出来**。

### 1.E 商务标（报价文件）完成后的审查

- **报价算术性复核**——逐条核「单价×数量=合价」并逐格比对（小数位按招标清单要求，通常 2 位）；分部/分项汇总、单位工程汇总（含措施费、其他项目费、规费、税金）累加 = 投标总价；投标总价与投标函总报价、开标一览表总价三方比对；小写→人民币大写互转比对；若招标文件有折扣/下浮，验证折后价落点且折扣必须落在开标一览表总价而非仅写备注；排查选择性报价（同一项两个价、含税/不含税矛盾、「暂按…」）；Excel 审计定位本应为公式却被硬编码的单元格。依据：12 号令第十九条（单价与数量乘积之和与总价不一致以单价为准；大写与小写不一致以大写为准；不接受修正的作废标）、财政部 87 号令第五十九条。自动化：**完全可自动化，纯算法**。
- **暂列金额、暂估价、计日工「照录」核查**——暂列金额按招标清单给定金额原样填写不得增删改；材料/工程设备暂估价按给定单价计入综合单价；专业工程暂估价按给定金额填写；计日工按给定项目与数量自主报综合单价并计算金额；核对投标总价确实包含上述给定金额；**总价合同下漏项不再找补**，报价前必须完成清单完整性核对。依据：《建设工程工程量清单计价规范》GB50500-2013、新《建设工程工程量清单计价标准》GB/T 50500-2024（2025-09-01 实施）。自动化：**高度可自动化**。
- **工程量清单响应性核对**——以招标清单为基线逐行比对五要素（项目编码、项目名称、项目特征、计量单位、工程量）必须一致；标记「投标有、清单无」的增项（涉嫌擅自变更清单）；标记「清单有、投标无」的漏项（**总价合同下最致命**）；检查单位是否被换算、工程量是否被擅自调整；项目特征不得删除或简化；措施项目按可竞争/不可竞争分类响应，安全文明施工费等不可竞争费不得下浮。依据：GB50500-2013 与 GB/T 50500-2024；各地清标定义条款。自动化：**高度可自动化**（需能解析清单 XML/Excel，扫描件需 OCR）。
- **投标函 / 开标一览表 / 报价明细表三表一致性核对**——抽取投标总报价（数字+大写）、工期/交货期、质量标准、项目负责人、报价有效期、折扣条款；两两比对（注意「90 日历天」vs「3 个月」表述不同但等价仍可能被判不一致）；确认招标文件规定的优先顺序并预演修正后最终报价；**重点排查折扣只写在备注或承诺函、未落到开标一览表总价（高频废标点）**。自动化：**高**。
- **模拟清标**——自建检查表覆盖算术性错误、缺漏项、报价构成异常、不平衡报价、与最高限价关系；与最高投标限价/控制价比对（总价超限即无效投标）；检测综合单价异常项；对可能被质询的异常项预置澄清材料（**澄清只能说明不能实质修改报价**）；预演修正两种结果是否改变相对排名。依据：各地招标文件清标条款与《标准施工招标文件》初步评审→详细评审→澄清程序。自动化：**部分**（算术/限价/单价离散度可自动；「报价构成是否合理」需经验判断）。
- **不平衡报价的合规边界与风险评估**——法律未禁止不平衡报价本身，红线是《招标投标法》第三十三条「不得以低于成本报价竞标」以及构成选择性报价/报价不唯一；正向风险（前期报高、后期报低）若后期工程量调减则亏损；反向风险（前期报低、后期报高）易被清标识别；核招标文件对不平衡报价的处置条款；结合合同计价方式（固定总价/固定单价/可调价）评估风险敞口。**「多高算不平衡」无统一量化标准，属经验之谈**。自动化：**低**（工具可辅助做单价离散度分析与异常项聚类标注，不能给合规结论）。
- **价格分算法解析与报价策略**——判定评标办法类型；还原基准价公式（有效投标评标价算术平均值 A；≥7 家去掉最高最低各 20% 或去一个最高一个最低；4–6 家剔除最高；<4 家取次低价；基准价 = A×K）；识别随机参数（K 值、Q 值由开标时随机抽取，报价无法完全精确命中基准价）；解析偏差扣分函数（如等于基准价满分、每低 1% 扣 0.6 分、每高 1% 扣 0.9 分 → 提示宜略低于基准价）；用公开历史同类项目中标价反推基准价区间。自动化：**部分**（公式解析与基准价区间反推可自动；最终报价决策不可自动）。
- **工期与质量标准等实质性承诺响应性核查**——抽取强制性要求（工期日历天/日历日/工作日口径、质量标准合格/优良/获奖等级、安全环保目标、报价有效期）；核投标函/开标一览表/技术标三处承诺是否满足或优于且不得低于；核对工期口径一致性（**日历天 vs 工作日最易错**）；检查三处承诺是否互相矛盾；排查附加条件是否导致被判偏离实质性条款。依据：条例第五十一条第（六）项。自动化：**高**。
- **报价文件交付前核查清单（人机分工汇总）**——格式（无空项、签署盖章齐全）→ 算术（单价×数量、汇总、总价、大小写、折扣落位）→ 清单（五要素一致、无漏项增项、单位未变、特征未改）→ 给定值（暂列/暂估/计日工照录、不可竞争费未下浮）→ 三表一致并按优先顺序预演修正 → 限价（总价与各部分不超）→ 承诺响应 → 唯一性（无选择性报价、无附加条件）→ 清标预案 → 数据参考。自动化：**清单化后绝大部分可自动化；报价策略与「是否低于成本」保留人工**。
- **中标价数据的公开性与可获取性**（报价参考底座）——公开数据的主体是**中标结果（中标人 + 中标金额），不是落标者报价**；唯一确认公开逐家投标报价的官方源是浙江 `ggzy.zj.gov.cn` 的「开标记录」详情页。各源能力、第三方商业源与合规缺口详见 [`bid-data-sources`] 调研结论（2026-09-11）。现实上限 = 中标价锚定 + 区间推演。自动化：**数据抓取可工程化**；但数据源授权与合规是前置条件，且「运行时派 agent 联网搜索」当前尚不具备。

### 1.F 模拟评标与复盘

- **投标文件符合性自查（废标项自查/清标自查）**——见 1.A；本仓已实现废标项检查。
- **评分办法逐项对标自评（响应矩阵）**——把评标办法拆成评分项树（一级/二级、分值、分档描述、客观/主观）；建「评分项—分值—评分标准要求—我方响应内容—支撑材料—自评得分—证据页码」对照表；客观分项逐项确认证明材料齐全、有效期、数量口径（「近三年」「不少于 3 个」）与认定口径；主观分项按分档（优/良/中/差）逐条自评，判断当前落在哪一档、还差哪些要素/篇幅才能升档；输出「得分预估 + 丢分清单 + 补强动作」。依据：《招标投标法》第 40 条、条例第 49 条。自动化：**高，本仓 ai-evaluation 可直接承担**。
- **模拟评标盲评（多评委独立盲评打分）**——①去标识化（公司名称、公章、logo、联系人替换为「投标人 A」）模拟暗标/盲评环境；②多个独立「AI 评委」按同一评分办法分别独立打分、互不可见；③汇总各评委每项得分计算极差与离散度，对分差大的评分项区分是「评分标准理解分歧」还是「投标文件表述不清」；④取最低分作风险预警分、均值作预期分；⑤有条件时请真实有经验者做人工盲评校准。依据：多地暗标盲评与席位制分散评标实践；主观分规范文件（甘肃《关于进一步规范政府采购项目主观评分的通知》）。自动化：**可自动化到「多 AI 评委独立盲评 + 离散度分析」；真实专家尺度无法替代**。
- **评委视角挑刺（红队评审）**——设「红队」角色：一名挑剔评委、一名竞争对手、一名监管视角；逐章追问「这一项评分标准我凭什么给分？证据在哪一页？」「资格条件满足吗？证明材料够吗？」「有没有前后矛盾、张冠李戴、承诺与证明材料不符？」；输出「评委质疑点清单」（问题—所在位置—为什么可能被质疑—应补充/修改的表述与材料）；重点排查商务与技术前后不一致、隐含承诺与商务条款冲突、引用法规标准已废止、图纸与文字不符。自动化：**可自动化**（AI 可扮演红队；深度专业判断与地方规则需人工）。
- **预演答疑与澄清答辩**——按评分办法与关键技术/商务点预判评委可能要求澄清的内容；建「问题—标准口径—可引用原文页码—可用补充材料」答疑问答库，确保答案只解释、不新增实质内容、不改报价与承诺；组织内部模拟答辩；**明确红线：只能澄清、说明、补正，不得借澄清补交资格材料、变更报价或改变实质性内容，不得主动提交未被询问的澄清**。依据：《招标投标法》第 39 条、条例第 52 条、12 号令第 19 条。自动化：**半自动**（AI 可生成预案问答库、模拟质询、校验答复是否「超范围」）。
- **开标现场记录与开标异议**——现场记录唱标内容与开标程序；发现程序违法或唱标有误**当场**提出异议。依据：条例第 44 条（应在开标现场提出，招标人应当场答复并制作记录）。自动化：**不可自动化**（软件仅提供记录模板与证据清单）。
- **中标候选人公示与评标结果公开数据抓取反推**——从全国/省级平台抓取同类项目：中标人、中标价、候选人前三名报价与排名、评标方法、工期、项目经理，以及部分地区公示的「被否决投标的名称、否决依据和原因」；计算中标价相对最高投标限价的下浮率、报价分布、竞争烈度；建「项目—招标人—中标人—报价—得分」库反推特定招标人的价格偏好与对手报价区间；政采项目关注「告知未中标人本人评审得分与排序」。依据：各地公示实例（重庆开州公示含否决原因；包头要求公示评标报告相关内容）。自动化：**高度可自动化**（本仓已有 bid-opportunity 基建与价格预测入口）；瓶颈是平台反爬、格式不一、得分明细覆盖不全。
- **评标结果异议（中标候选人公示期内）**——招标人应自收到评标报告之日起 3 日内公示、公示期不少于 3 日；在公示期内以投标人/利害关系人身份向招标人提出书面异议；招标人自收到之日起 3 日内答复，答复前暂停招标投标活动；保留送达凭证与答复件。依据：条例第 54 条。自动化：**不可自动化**（须实名、书面、含法律判断；软件仅做时限提醒与文书模板）。
- **招投标投诉与政府采购质疑、投诉**——工程类：自知道或应当知道之日起 **10 日内**向有关行政监督部门投诉（条例第 60 条、七部委 11 号令）；政采类：知道或应知之日起 **7 个工作日内**向采购人书面质疑，采购人 7 个工作日答复，对答复不满或未答复的在答复期满后 **15 个工作日内**向同级监管部门投诉（《政府采购法》第 52、53、55 条，财政部 94 号令）。自动化：**低**（法律判断与实名程序必须人工/律师；软件仅做时限提醒与文书模板）。
- **评标澄清与说明的应对（收到澄清通知时）**——先判定澄清事项性质（含义不明确 / 明显文字或计算错误 / 同类问题表述不一致）；只在原投标文件范围内解释，不改报价、不改承诺、不补资格材料；以书面形式在时限内回复并留痕；不主动追加未被询问的说明；若评委有暗示、诱导或要求超范围补正，注意固定证据。依据：条例第 52 条、12 号令第 19 条。自动化：**半自动**。
- **中标/落标复盘会（差距归因）**——中标后把每项实际得分与自评分对比定位「高估/低估」；落标后按四问归因：价格差距（报价与中标价差、下浮率、是否遭遇低价竞争）、技术分差距（哪几项低于中标人、差多少）、商务分差距（业绩/证书/人员少在哪）、废标原因（否决条款是什么）；形成「失利归因表」（原因分类—责任环节—改进措施—责任人—下次跟进）；把可复制的失分点转为 checklist 模板与知识库条目。依据：招投标数据复盘实务文章与企业实践。自动化：**半自动**（真实得分与对手报价数据获取是瓶颈）。
- **废标与否决原因台账复盘**——从各地公示抽取「被否决投标的投标人名称、否决依据和原因」，归类到标准码表（形式/资格/保证金/报价/实质响应/串通或弄虚作假）；统计自家与行业高频否决项形成「最高频废标项 TOP N」，固化为交标前 checklist。依据：条例第 51 条；重庆开州等地公示实例；行业统计（自媒体数据，标注为经验数据）。自动化：**可自动化**（公示抓取 + 原因分类 + 统计）。
- **复盘数据沉淀入企业知识库**——建三类库：**中标案例库**（可复用技术方案段落、亮点、图表）、**失标/否决案例库**（失败原因、否决条款、整改）、**评分点素材库**（按评分项标签化的证书/业绩/人员/方案片段）；每份投标文件打标签（行业、项目类型、招标人、评分办法版本、评分项、命中率、复盘结论）；把复盘结论结构化写回库形成「评分项—素材—失分教训」索引；定期维护（剔除过期证书业绩、更新法规与评分办法版本、去重脱敏）。自动化：**高度可自动化**（关键在入库流程制度化与标签治理）。

## 3. 差距分析

### 3.1 已被实质覆盖（工程化扎实）

- **否决投标/废标项自查流水线**（rejection-check）——已覆盖行业方法 1.A 的核心，且带输入签名失效、滚动状态机、程序化错别字定位等工程质量。
- **全文关键数据/承诺一致性自查**——`contentGenerationTask` 的一致性审计 + `rejectionCheckTask` 的逻辑谬误检查。
- **图表化改造**——配图规划/生成/复用链路完整。
- **篇幅与正文字数控制**——确定性算法控制，是同类工具少见的能力。
- **文档属性与隐藏指纹自查**——本仓库最成熟的一类能力。
- **投标人之间两两比对（元数据与精确文本维度）**——目录/正文/图片/元数据四维、招标引用白名单剔除误报、可导出。
- **相同错别字自查**——程序化校准使误报低、定位可信。
- **评分点与目录结构对齐**——目录层机械校验可靠。
- **模拟评标（单评委版）**——链路完整可用。
- **企业自有素材库复用**（文/图分流）——可用。

|---|---|---|
| **投标报价算术性复核 + 大小写/单位/币种一致 + 限价比对** | 全仓零实现；零漏项、纯算法、最该优先自动化；投标函/开标一览表/明细表不一致是高频致命废标点 | 低 |

| **暗标/匿名合规检查**（敏感实体扫描 + 格式参数核对 + 元数据去名） | 技术标出现投标人名称/logo/人员姓名按无效投标处理，损失最大；文本级敏感词 + 格式 + 元数据清理可高度自动化 | 中 |
| **联合体投标合规核验 / 分包合规核验** | 均属可文本核对、评标直接否决的条款 | 中 |

### 3.4 三个系统性断点

**断点 1：诊断 → 修复的链条断了（最影响成交）**

废标项检查、AI 评标、查重、一致性审计**全部「只报告不改写」**：finding 只给 `suggestion`，不定位到 `technical_plan_outline_nodes` 节点、不能自动/半自动修改替换正文；用户只能删除条目或复制错字/原文，无一键修复或跳回正文修改。更关键的是——**投标文件不能从技术方案正文直接回读**（只有招标文件侧有 `importTenderFromTechnicalPlan`，投标文件侧无对应入口，已 grep 确认）。因此对「已写好的标书」的回检是**外挂式**的：先导出成品、再上传，"已完成的标书"与编辑中的正文完全脱节。**这使「检出」无法自动转成「改好」。**

**断点 2：纯规则类检查整块空白**

报价算术、大小写互验、三表一致、限价、工程量清单 diff、暗标去名与格式核对、投标有效期/保证金要素核对——**全仓零实现**（已 grep 确认）。这类检查零漏项、100% 可自动化、且是高频致命废标点，投产比最高。

**断点 3：Step06「扩写改写」是占位页**

`TechnicalPlanHome.tsx:1443` 为「正在开发中，敬请期待」。正文完成后**没有**手动扩写/缩写/润色/人工校准入口（只能整篇重生成或单节重生成），也没有版本对比/回滚。而这正是「改得更好」最直接的交互缺口。能力其实已在 `contentGenerationTask.cjs`（`runSectionWordAdjustments`/`runTotalWordAdjustments`）里，只是被封在生成任务内。

### 3.5 其他需知的能力边界与风险

- **离线模式的可用性事实**：`configStore.cjs` 的 `offline_mode`（默认 false）会在 `aiService.cjs:338` 门控全部 AI 请求 → **离线时所有 AI 类检查（废标项/评标/正文生成）整体不可用**（查重的元数据维度除外）。这既是可用性事实，也提示保密风险——整条「标书完成后改进」链路都要把招标文件与投标正文全文送第三方大模型，而投标文件含商业秘密、招标文件常带保密条款。相关设计见 `docs/design/全局离线模式方案.md`。
- **采购方式维度**：现有方法调研与实现几乎只覆盖「招标」（公开/邀请招标）。政府采购的竞争性谈判、竞争性磋商、询价、单一来源，其「评标」与「评审」口径、报价轮次、响应文件组成均不同，工具未区分。
- **行业/标段类型维度**：正文与评标分析几乎全基于「施工组织设计/工程类」，而产品定位是通用「技术方案」（知识库提示词已覆盖货物/服务）。勘察设计、监理、EPC、货物/服务/IT/物业类的评分要点与改进手法差异大，工具适配缺口未系统评估。
- **素材来源权属**：知识库无「来源/权属」登记、无「员工带入前雇主素材」的同源检测，有真实侵权判例佐证（见 1.D），应作为独立能力建设（素材来源登记 + 同源/残留检测 + 脱敏）。
- **提示词版本漂移**：`client/src/shared/prompts/rejectionPrompts.ts` 定义了 v1 版检查提示词，但其中的 5 个检查类消息构造器**仅被 `prompts/index.ts` 再导出、无任何调用方**；实际生效的是 Main 内联的 v2 多文档提示词（`rejectionCheckTask.cjs`），两处文案已不一致（v1 输入单文档、v2 引入 `bidDocumentId` 与多文件）。
